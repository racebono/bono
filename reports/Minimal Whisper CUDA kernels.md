# Keep three quantized CUDA matrix specializations

**Bono can target Q5_0, Q5_1 and Q8_0 optimized CUDA matrix multiplication while retaining fallback paths for other formats.** These three weight types cover its current downloadable quantized models; Q5_0 covers the recommended large-v3-turbo model. Removing the other sixteen MMQ template instances targets **41.01 accumulated minutes of compilation tasks**, 37.57% of measured CUDA task duration. This is not a prediction of wall-clock savings. Preserve floating-point kernels, matrix-vector kernels, conversions and internal Q8_1 activation quantization. The safe change belongs in both CMake and CUDA dispatch; deleting source files alone breaks linking. No reduced build or inference benchmark has yet validated this proposal.

## The current menu needs three quantized weight types

Bono recommends `ggml-large-v3-turbo-q5_0.bin`. Its download menu reads the live Hugging Face repository and accepts root-level `ggml-*.bin` files without a quantization allowlist. On 20 October 2026 that catalog offers unquantized models plus **Q5_0, Q5_1 and Q8_0**, with no Q4, K, IQ or MXFP4 models. This establishes the current product requirement, rather than observed user selections. ([Recommended model and catalog parser](/D:/Projects/bono/src/app/topbar/audio/whisper.rs:51), [live catalog](https://huggingface.co/ggerganov/whisper.cpp/tree/main))

The catalog can change, and persisted configuration accepts an arbitrary model path even though the inspected UI has no custom-file picker. Broader model compatibility therefore matters. Bono pins native Whisper revision `2eeeba56e9edd762b4b38467bab96c2517163158`; its quantizer accepts **ten destinations**: Q4_0, Q4_1, Q5_0, Q5_1, Q8_0 and Q2_K through Q6_K. It rejects IQ and MXFP4 destinations. K formats are therefore credible custom-model scope, although accepted quantizer names do not prove every model geometry can use every K format. ([Model loading](/D:/Projects/bono/src/app/topbar/audio/whisper.rs:442), [pinned quantizer](https://github.com/ggml-org/whisper.cpp/blob/2eeeba56e9edd762b4b38467bab96c2517163158/examples/common-ggml.cpp#L6))

Quantized files still contain floating-point tensors. The loader uses F16 convolution weights except for F32 models, and F32 positional embeddings, norms and biases. **F16/F32 matrix operations remain necessary even for Q5_0-only use.** ([Pinned loader](https://github.com/ggml-org/whisper.cpp/blob/2eeeba56e9edd762b4b38467bab96c2517163158/src/whisper.cpp#L1677))

## Remove optimized MMQ paths without banning formats

MMQ is quantized matrix-matrix multiplication; MMVQ handles quantized matrix-vector work. The pinned dispatcher normally selects MMVQ first for eligible operations with at most eight columns. Larger work can select MMQ, including on modern NVIDIA GPUs. Consequently Q5_0 MMQ is useful for Bono; deleting every MMQ specialization could sacrifice encoder or batched projection performance. Exact runtime dispatch counts have not been profiled. ([CUDA dispatch](https://github.com/ggml-org/whisper.cpp/blob/2eeeba56e9edd762b4b38467bab96c2517163158/ggml/src/ggml-cuda/ggml-cuda.cu#L2181), [MMQ selection](https://github.com/ggml-org/whisper.cpp/blob/2eeeba56e9edd762b4b38467bab96c2517163158/ggml/src/ggml-cuda/mmq.cu#L262))

**Retain Q5_0/Q5_1/Q8_0 MMQ and retain all existing MMVQ, dequantization and cuBLAS fallback paths initially.** Disabled MMQ types can then use MMVQ for eligible small-column work or convert weights to floating point for cuBLAS GEMM. This reduces optimized specializations rather than declaring those model formats unsupported. The fallback can cost throughput and temporary GPU memory, so validate custom Q4/K models separately. `GGML_CUDA_FORCE_CUBLAS` changes dispatch but does not stop CMake compiling MMQ instances. ([Fallback conversion and GEMM](https://github.com/ggml-org/whisper.cpp/blob/2eeeba56e9edd762b4b38467bab96c2517163158/ggml/src/ggml-cuda/ggml-cuda.cu#L1286), [source inclusion](https://github.com/ggml-org/whisper.cpp/blob/2eeeba56e9edd762b4b38467bab96c2517163158/ggml/src/ggml-cuda/CMakeLists.txt))

Keep `convert.cu`, `getrows.cu`, ordinary attention and tensor operations, and floating-point matrix/vector paths. In particular, **Q8_1 is an internal activation representation**, distinct from Q8_0 model weights: Q5_0 MMQ/MMVQ depends on Q8_1 activation quantization. Pruning model-weight specializations does not justify removing it. ([MMVQ implementation](https://github.com/ggml-org/whisper.cpp/blob/2eeeba56e9edd762b4b38467bab96c2517163158/ggml/src/ggml-cuda/mmvq.cu#L14), [activation quantization](https://github.com/ggml-org/whisper.cpp/blob/2eeeba56e9edd762b4b38467bab96c2517163158/ggml/src/ggml-cuda/quantize.cu))

## Sixteen instances account for 41 accumulated minutes

The completed cold build logged **6,548.941 seconds** across 126 CUDA object tasks. Nineteen MMQ instances account for 2,934.518 seconds. Keeping the catalog's three instances retains 474.009 seconds and removes **2,460.509 seconds**, or 83.85% of MMQ task duration and 37.57% of all CUDA task duration. Keeping only Q5_0 would remove 2,758.687 seconds; the additional reduction is just 298.178 accumulated seconds while discarding optimized paths for existing menu choices. ([Completed Ninja log](/D:/Projects/bono/target/cold-test/release/build/whisper-rs-sys-6a87b0d7dbab4545/out/build/.ninja_log))

These durations overlap and include contention. **They cannot be subtracted from the roughly ten-minute local wall time**, or translated directly into CI savings under its two-job limit. They rank worthwhile experiments; only a clean reduced build establishes the result. FlashAttention was already disabled, yet its source files consumed another 801.533 accumulated seconds. Excluding those translation units is a separate source/dispatch audit, not another runtime flag to disable. ([Build cache](/D:/Projects/bono/target/cold-test/release/build/whisper-rs-sys-6a87b0d7dbab4545/out/build/CMakeCache.txt), [Ninja log](/D:/Projects/bono/target/cold-test/release/build/whisper-rs-sys-6a87b0d7dbab4545/out/build/.ninja_log))

## One allowlist must govern compilation and dispatch

Add a fork-owned MMQ type option, defaulting to the full upstream set, and choose Q5_0/Q5_1/Q8_0 for Bono. This is a proposed option, not an existing upstream flag. Use that same definition to select instance sources and guard both the launch switch and `ggml_cuda_should_use_mmq`. The latter must return false for omitted types so execution reaches retained fallback paths. Direct calls to explicit template instances otherwise leave unresolved symbols after source exclusion. MMQ-only pruning does not require banning formats in backend `supports_op`. ([MMQ switches](https://github.com/ggml-org/whisper.cpp/blob/2eeeba56e9edd762b4b38467bab96c2517163158/ggml/src/ggml-cuda/mmq.cu), [template declarations](https://github.com/ggml-org/whisper.cpp/blob/2eeeba56e9edd762b4b38467bab96c2517163158/ggml/src/ggml-cuda/mmq.cuh#L4051))

Before shipping, verify clean build/link and baseline-versus-reduced inference for Q5_0, Q5_1, Q8_0, unquantized F16 and representative custom Q4/K models. Cover short/long audio, beam/prompt behavior, CPU/Vulkan loading, GPU memory and encoder/decoder timing. Exercise the configured architecture paths (`75-virtual;86-real;120-real`) on representative supported GPUs. Then measure native CI wall time with identical runner and job settings. **The investigation supports this as the first pruning experiment; correctness, runtime performance and the CI target remain unmeasured.**
