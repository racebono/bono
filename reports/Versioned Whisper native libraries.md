# Choose versioned Whisper libraries for Bono

**Versioned Windows whisper.cpp binaries are available from official GitHub releases and Whisper.net’s NuGet packages, but neither is a drop-in replacement for Bono’s current native build.** Official bundles offer CPU, OpenBLAS, or CUDA; Whisper.net additionally offers Vulkan and OpenVINO. Both distribute runtime DLLs rather than the static libraries Bono currently links. Their CUDA builds retain custom matrix kernels and enable FlashAttention by default. Bono instead pins native version 1.8.3, combines CPU + CUDA + Vulkan, and disables CUDA FlashAttention. An exact-match custom static release remains the lowest-risk way to preserve that configuration while removing native compilation from routine CI.

## Official bundles offer CUDA without Vulkan

The official [v1.9.4 release](https://github.com/ggml-org/whisper.cpp/releases/tag/v1.9.4) points to [b5130 binaries](https://github.com/ggml-org/whisper.cpp/releases/tag/b5130), identifying the same commit, `927cfce`. Pinned downloads include [CPU x64](https://github.com/ggml-org/whisper.cpp/releases/download/b5130/whisper-bin-x64.zip), [OpenBLAS x64](https://github.com/ggml-org/whisper.cpp/releases/download/b5130/whisper-blas-bin-x64.zip), [CUDA 11.8 x64](https://github.com/ggml-org/whisper.cpp/releases/download/b5130/whisper-cublas-11.8.0-bin-x64.zip), and [CUDA 12.4 x64](https://github.com/ggml-org/whisper.cpp/releases/download/b5130/whisper-cublas-12.4.0-bin-x64.zip). **There is no Windows Vulkan asset in this release.** The workflow builds portable CPU variants with dynamic backend loading; OpenBLAS adds BLAS and CUDA adds the CUDA backend. The inspected CPU ZIP contains DLLs and executables, without headers, `.lib` files, or a CMake development package. ([Assets](https://api.github.com/repos/ggml-org/whisper.cpp/releases/tags/b5130), [build and packaging workflow](https://github.com/ggml-org/whisper.cpp/blob/v1.9.4/.github/workflows/release.yml))

Despite their `cublas` filenames, the CUDA packages are **not cuBLAS-only builds**. Source defaults retain MMQ quantized matrix multiplication, MMF floating-point matrix multiplication, and FlashAttention tile/MMA kernels. `GGML_CUDA_FA=ON` and `GGML_CUDA_FA_ALL_QUANTS=OFF` include vector FA specializations for f16/f16, q4_0/q4_0, q8_0/q8_0, and bf16/bf16, excluding the additional vector FA quantization combinations. This does **not** remove ordinary quantized weight matrix kernels. `FORCE_MMQ` and `FORCE_CUBLAS` are both off; CUDA graphs are off. These are source/workflow-derived settings, not a disassembly of the downloaded GPU binaries. ([Options](https://github.com/ggml-org/whisper.cpp/blob/v1.9.4/ggml/CMakeLists.txt), [kernel selection](https://github.com/ggml-org/whisper.cpp/blob/v1.9.4/ggml/src/ggml-cuda/CMakeLists.txt))

Their expected architecture list is `50-virtual;61-virtual;70-virtual;75-virtual;80-virtual;86-real;89-real;90-virtual`. `virtual` embeds PTX for driver compilation; `real` embeds architecture-specific machine code. Neither package has native Blackwell targets. ([Architecture defaults](https://github.com/ggml-org/whisper.cpp/blob/v1.9.4/ggml/src/ggml-cuda/CMakeLists.txt))

## Whisper.net adds versioned Vulkan DLLs

Whisper.net **1.9.1** supplies separately versioned [CPU](https://www.nuget.org/packages/Whisper.net.Runtime/1.9.1), [NoAvx](https://www.nuget.org/packages/Whisper.net.Runtime.NoAvx/1.9.1), [CUDA 13](https://www.nuget.org/packages/Whisper.net.Runtime.Cuda.Windows/1.9.1), [CUDA 12](https://www.nuget.org/packages/Whisper.net.Runtime.Cuda12.Windows/1.9.1), [Vulkan](https://www.nuget.org/packages/Whisper.net.Runtime.Vulkan/1.9.1), and [OpenVINO](https://www.nuget.org/packages/Whisper.net.Runtime.OpenVino/1.9.1) packages. These native DLLs can in principle be consumed outside .NET. The release uses whisper.cpp 1.8.5, commit `f24588a272ae8e23280d9c220536437164e6ed28`, rather than Bono’s native revision. The inspected CPU NuGet package has DLLs and no headers or import/static libraries. ([Release](https://github.com/sandrohanea/whisper.net/releases/tag/1.9.1), [submodule](https://api.github.com/repos/sandrohanea/whisper.net/contents/whisper.cpp?ref=1.9.1), [packaging script](https://github.com/sandrohanea/whisper.net/blob/1.9.1/windows-scripts.ps1))

The Windows builds use `GGML_NATIVE=OFF`. Normal x64 builds enable AVX, AVX2, FMA and F16C; NoAvx disables those four. GPU packages retain CPU fallback and enable their named backend separately. Other GPU backends and Windows BLAS remain off. **Do not assume combining CUDA and Vulkan packages creates a supported combined-backend build:** they ship their own common DLLs and renamed backend dependencies. ([Build flags](https://github.com/sandrohanea/whisper.net/blob/1.9.1/windows-scripts.ps1), [target renaming](https://github.com/sandrohanea/whisper.net/blob/1.9.1/CMakeLists.txt))

CUDA uses toolkits **12.4.1 or 13.0.1** and the same FA/MMQ/MMF inclusion pattern described above, with no package-specific kernel pruning. CUDA 12 targets the architecture list above; CUDA 13 targets `75-virtual;80-virtual;86-real;89-real;90-virtual;120a-real;121a-real`. Thus CUDA 13 excludes pre-Turing devices, while providing native Blackwell targets. Vulkan builds shader variants according to compiler support for cooperative matrices, integer dot products and bfloat16; the exact published extension inventory was not verified. ([CUDA workflow](https://github.com/sandrohanea/whisper.net/blob/1.9.1/.github/workflows/windows-cuda-native-build.yml), [pinned CUDA source](https://github.com/ggml-org/whisper.cpp/blob/f24588a272ae8e23280d9c220536437164e6ed28/ggml/src/ggml-cuda/CMakeLists.txt), [Vulkan source](https://github.com/ggml-org/whisper.cpp/blob/f24588a272ae8e23280d9c220536437164e6ed28/ggml/src/ggml-vulkan/CMakeLists.txt))

A commit-labelled [preview archive](https://github.com/sandrohanea/whisper.net/releases/download/preview-nativelibs-d1be6fd/native-runtimes.zip) also exists. Its configuration must be checked separately; the stable flags above do not establish preview behavior.

## Bono needs an explicit prebuilt integration

Bono’s [lockfile](D:/Projects/bono/Cargo.lock:5179) pins its whisper-rs fork to `d2787715…`; the cached submodule is native `2eeeba56…`, version **1.8.3**. Its build script unconditionally runs CMake and links static `whisper`, `ggml`, `ggml-base`, `ggml-cpu`, `ggml-cuda`, and `ggml-vulkan`. Skipping binding generation does not skip compilation. An MSVC `.lib` can be either a static archive containing implementation or an import library referring to a DLL; generating an import library for these packages would not reproduce Bono’s static linkage. DLL adoption needs matching bindings, build-script changes and runtime packaging. ([Pinned build script](C:/Users/Alex/.cargo/git/checkouts/whisper-rs-8c1dccfa435c963c/d278771/sys/build.rs))

For the closest fit, publish those six static libraries from the exact native commit, together with headers/bindings, hashes and a build manifest. Preserve CPU + CUDA + Vulkan, `GGML_CUDA_FA=OFF`, and the intended GPU architectures. Key artifacts by native commit, MSVC target/runtime, toolkit and options. Compiled FA availability and Bono’s runtime `flash_attn` setting are separate: using an FA-enabled package does not automatically activate it. CUDA link/runtime requirements also remain after native compilation is removed. ([Bono configuration](D:/Projects/bono/.cargo/config.toml:19), [Windows workflow](D:/Projects/bono/.github/workflows/windows.yml:67))

**Recommendation:** use the public packages for evaluating DLL integration, and a custom versioned static release for the current Bono configuration. No examined public artifact established exact revision, linkage, combined-backend and kernel equivalence. Binary ABI compatibility and inference correctness still require testing before shipping.
